# Контекст проекта: Pet-проект интернет-магазина

## Кто пользователь и зачем это нужно

Пользователь — начинающий full-stack разработчик (резюме показывает: React 18, TypeScript, Vite, Node.js, Express, REST API, JWT, PostgreSQL/MongoDB, Prisma, WebSockets; также есть опыт с AI/LLM-интеграциями — Whisper STT, TTS). B.Sc. Informatik, живёт/работает в немецкоязычном регионе (DE B2, есть Anerkennung диплома в Германии), сейчас в поиске работы ("Verfügbar nach Absprache").

**Цель этого проекта**: pet-проект для портфолио, который закроет пробелы в резюме и покажет уровень выше junior. У пользователя будет отдельный сайт-визитка со всеми проектами — этот магазин будет одним из показательных проектов там.

## Как пришли к выбору "интернет-магазин"

Обсуждали разные варианты pet-проектов (канбан-доска, агрегатор с внешним API, соцсеть, AI-приложение). Пользователь сам склонился к идее интернет-магазина / чего-то подобного. Решили, что e-commerce — сильный выбор, потому что естественно требует:
- БД + ORM (Prisma + PostgreSQL — уже есть в стеке пользователя)
- Аутентификация и роли (покупатель/админ)
- Корзина + checkout + оплата (Stripe, тестовый режим)
- Админ-панель
- Docker + CI/CD (GitHub Actions) — **этого сейчас нет в резюме, это главный пробел, который проект должен закрыть**
- Базовые e2e-тесты (Playwright) — тоже пробел

Важно: договорились НЕ клонировать готовый шаблон 1:1 (типа Vercel Commerce / Medusa) как есть, а использовать чужие макеты/структуру только как референс, чтобы на собеседовании можно было объяснить архитектурные решения.

## Дизайн — что искали и что не подошло

Пользователь хочет **"стильно и современно"**. Перебирали Figma-шаблоны с Figma Community:
- Первые найденные варианты (яркие 3D-иллюстрации, градиенты, "милый" мобильный стиль вроде "E-Commerce, Marketplace UI Components, UI Kit" с фиолетовыми шариками и подарками) — **пользователю не понравились**, выглядит устаревше/несерьёзно для портфолио.
- Показывали макет форм Sign in / Register (бренд "StyleSage", основа — Open Fashion UI Kit) — структура/раскладка понравилась, но **визуальный стиль не понравился**: закруглённая оранжевая pill-кнопка, дефолтный шрифт, серые кружки-иконки соцсетей — выглядит как generic bootstrap-шаблон.

**Договорённое направление стиля**: минимализм в духе Aesop/COS/Vercel/Linear — крупная чистая типографика (Inter/Geist), сдержанная палитра (чёрный/белый + один акцент, БЕЗ оранжевого/ярких градиентов), прямоугольные или слегка скруглённые кнопки (radius 4-8px, не pill), много whitespace, возможно split-screen компоновка (форма слева, крупное фото товара справа).

Рекомендованные референсы (можно смотреть заново, дублировать к себе в Figma):
- https://www.figma.com/community/file/1255525288557123779/e-commerce-free-ui-kit (минимализм, одежда — лучший вариант по стилю)
- https://www.figma.com/community/file/1488457068110209569/new-updated-2026-e-commerce-marketplace-ui-kit-free-figma-template (полный флоу экранов — каталог/карточка/checkout, но обложка кита слишком "яркая", смотреть саму библиотеку компонентов, не превью)
- https://www.figma.com/community/file/1201935147948130925/black-and-white-web-mobile-ui-kit (нейтральная база дизайн-системы)

## Решение по инструментам: почему shadcn/ui MCP

Пользователь спросил, есть ли способ дать агенту (мне) лучший "вкус" в дизайне, чтобы не получалось шаблонно. Решение — подключить **shadcn/ui MCP-сервер**. Логика: shadcn/ui — это уже устоявшаяся, продуманная дизайн-система с хорошей шкалой отступов/цветов (используется в Vercel/Linear-подобных продуктах), и через MCP агент может напрямую брать реальные, вылизанные компоненты вместо того, чтобы придумывать CSS "на глаз" — это должно снять проблему "стиль не тот".

**Что уже сделано:**
- Создана папка `c:\Users\tanja\OneDrive\Desktop\projects\shop` — это рабочая директория будущего проекта
- В ней создан файл `.mcp.json`:
```json
{
  "mcpServers": {
    "shadcn": {
      "command": "npx",
      "args": ["shadcn@latest", "mcp"]
    }
  }
}
```
- На машине пользователя есть Node v24.11.1 и npm 11.6.2, **pnpm НЕ установлен** (использовать npx, не pnpm dlx)

**Что нужно сделать пользователю / следующей сессии:**
1. Открыть Claude Code именно в директории `shop` (или сменить рабочую директорию текущей сессии на неё), чтобы подхватился `.mcp.json`
2. Выполнить `/mcp` и убедиться, что `shadcn` в статусе "Connected"
3. Дальше — застаффолдить сам проект (ещё не сделано!): Next.js + TypeScript + Tailwind + shadcn/ui в этой папке
4. Взять референсы из Figma-макетов выше (пользователь ещё не выбрал финальный, возможно доработает сам) как основу структуры страниц, но стилизовать через shadcn/ui-компоненты в минималистичном ключе, описанном выше — НЕ копировать оранжево-pill стиль

## Технический стек проекта (согласовано, но не финализировано)

- Frontend: Next.js (SSR ради SEO для e-commerce) + TypeScript + Tailwind + shadcn/ui — возможная смена с Vite, который пользователь использовал раньше
- Backend: либо Next.js API routes, либо отдельный Node/Express (пользователь уже умеет Express — решить в след. сессии)
- ORM/DB: Prisma + PostgreSQL (уже есть в стеке пользователя)
- Оплата: Stripe (тестовый режим)
- Auth: JWT, роли покупатель/админ
- Инфраструктура: Docker + docker-compose, GitHub Actions CI — **это ключевая цель проекта, обязательно не забыть**
- Тесты: Playwright для e2e хотя бы по ключевому флоу (просмотр товара → корзина → checkout)

## Решено (2026-08-23)

- **Макет**: https://www.figma.com/community/file/1255525288557123779/e-commerce-free-ui-kit (минимализм, лучший вариант по стилю). Дизайн ещё будет дорабатываться/меняться в процессе.
- **Ниша**: чайный магазин — чаи (сорта), чашки, заварники, наборы. Пользователь сам любитель чая, хочет раскрутить эту тему. Интерфейс адаптировать под "чайную" эстетику (тёплые нейтральные тона поверх минималистичной базы), но не уходить от согласованного минимализма (без ярких/пёстрых элементов).
- **Название/бренд**: **Leaf & Cup**
- **Backend**: Next.js API routes (не отдельный Express-сервер) — единый репозиторий/деплой.
